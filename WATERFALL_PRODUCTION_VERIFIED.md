5. **Gap created:** Weeks between Aug 17 backfill end and Sep 7 workflow run were missing

**Why the original Slack response showed "$0 net change":**

- Prior week (Aug 31) missing
- Original synthesis presented "$0" with caveat, creating ambiguity

## Design Patterns Reinforced

### 1. "Verify the fix in production, not just in the diff"

**Before:** Assume workflow will work next Monday (5-day gap to find bugs)
**After:** Manual trigger RIGHT NOW confirms it works (or catches typos/dependency issues immediately)

**Quote from user:**
> "Don't wait until next Monday to find out if the fix actually works — that's a five-day gap where nobody would notice if the workflow YAML fix has its own bug."

### 2. "Don't leave known-bad data when the fix is cheap"

**Before:** Accept 2-week gap, document as limitation
**After:** 5-minute backfill closes gap entirely, no compromises

**Quote from user:**
> "At ~5 minutes of runtime, there's no real reason to leave known-bad historical data in place when the fix is already identified and cheap to apply."

### 3. "Absence of data ≠ zero movement"

**Before:** Present "$0 net change" with caveat when missing comparison data
**After:** Refuse to present any movement metric when data incomplete

**Core principle:**
When comparison period has incomplete data, state "cannot compute movement" explicitly. Never qualify a potentially wrong number.
