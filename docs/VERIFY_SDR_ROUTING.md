# Verifying SDR/ARR Question Routing After Schema Fix

## Background

After registering 62 missing columns (High Priority #1), we need to verify whether SDR/ARR questions still route to `dynamic_query` first (then exception/fallback) or if routing behavior changed.

**Key question:** Does fixing `data_dictionary` registration affect routing, or is routing independent of schema?

**Hypothesis:** Routing is independent (classifier uses `HANDLER_DESCRIPTIONS` and confidence, not schema). But needs verification.

---

## Verification Steps

### When an SDR/ARR question is asked (naturally):

**Examples of triggering questions:**
- "How's [name]'s call quality this month?"
- "Show me SDR metrics for [name]"
- "What's our ARR by customer?"
- "SDR pipeline generated by [name]"

**Immediate check after question answered:**

```bash
# 1. Get the most recent query_cost_log entry
export $(grep -v '^#' .env | xargs) 2>/dev/null
psql $SUPABASE_DB_URL -c "
  SELECT id, question, reason_tag, outcome, answered
  FROM query_cost_log
  ORDER BY created_at DESC
  LIMIT 1;
"
```

**Interpretation:**

| Scenario | Evidence | Meaning |
|----------|----------|---------|
| **No entry in query_cost_log** | Question not in log at all | ✅ Routed directly to dedicated handler (query_sdr_metrics, query_call_quality, etc.) - EXPECTED BEHAVIOR |
| **Entry with outcome=exception** | Question in log, exceptioned | ⚠️  Still routing to dynamic_query, still failing (same old pattern) |
| **Entry with outcome=answered_cleanly** | Question in log, succeeded | ⚠️  Now routing to dynamic_query AND succeeding - VERIFY ANSWER CORRECTNESS |
| **Entry with outcome=other_fallback** | Question in log, fell back | Same as exception case - routing to dynamic_query first, falling back |

**If entry exists (routed to dynamic_query):**

```bash
# 2. Check what tables were queried
psql $SUPABASE_DB_URL -c "
  SELECT id, question, primitives_fired
  FROM query_cost_log
  WHERE id = [ID_FROM_STEP_1];
"

# 3. Check fallback_log for the same question
psql $SUPABASE_DB_URL -c "
  SELECT question, trigger, fast_path_attempted, queries_run::jsonb
  FROM fallback_log
  WHERE question ILIKE '%[KEYWORD_FROM_QUESTION]%'
  ORDER BY created_at DESC
  LIMIT 1;
"
```

**Look for:**
- `queries_run` containing `sdr_metrics`, `sdr_users`, `arr_by_customer`
- If present: dynamic_query successfully queried the now-visible tables
- If absent: dynamic_query still exceptioned, fell back to handler

---

## Expected Outcomes

### Best case: No query_cost_log entry
- Question routed directly to dedicated handler
- Schema fix didn't change routing (as expected)
- System working as designed

### Acceptable case: query_cost_log entry with exception, clean fallback
- Question still routes to dynamic_query first (confidence < 0.80?)
- dynamic_query still exceptions (different error? or still table-related?)
- Falls back to correct handler
- User gets correct answer
- Not ideal (exception overhead) but safe

### Concerning case: query_cost_log entry with success, wrong answer
- Question routes to dynamic_query
- dynamic_query succeeds (tables now visible)
- But produces wrong/incomplete results (didn't use specialized handler logic)
- User sees incorrect data
- **ACTION REQUIRED:** Investigate why classifier didn't route to specialized handler
